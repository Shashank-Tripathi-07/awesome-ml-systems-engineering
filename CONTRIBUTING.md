# Contribution Guidelines

Thank you for considering contributing to **Awesome ML Systems Engineering**! This is a curated list, meaning quality matters more than quantity. Please read these guidelines before submitting a pull request.

## The Pull Request Process

1. Search existing entries before adding a new one to avoid duplicates.
2. Make an individual PR for each suggestion.
3. Use the following format for new entries:

   ```
   - [Resource Name](url) - Short description explaining why it's valuable for ML Systems Engineering.
   ```

4. Descriptions must:
   - End with a period.
   - Be objective and factual, not promotional.
   - Explain **why** the resource matters, not just what it is.
   - Be written in English.

5. New entries should be added in alphabetical order within their section where possible.

6. Check that your link works and points to the correct page.

## Criteria for Inclusion

A resource should meet **all** of the following:

- **Relevant** -- directly useful to someone working on or learning ML Systems Engineering (training, inference, compilers, hardware, distributed systems, data pipelines, MLOps, or adjacent topics).
- **High quality** -- well-written, accurate, and maintained. Abandoned or outdated resources should not be added.
- **Publicly accessible** -- free to access, or at minimum has meaningful free content (paywalled content is acceptable if widely considered essential).
- **Non-promotional** -- not a vendor landing page, marketing material, or SEO content. Official documentation from open-source projects is fine.

## What NOT to Submit

- Personal blogs with only one relevant post (link to the post in an existing section instead if it's exceptional).
- Tools or libraries that are experimental, unmaintained, or have fewer than 50 GitHub stars (unless uniquely valuable and the only resource of its kind).
- Courses or books that are purely introductory ML with no systems focus.
- Duplicate resources -- if it's already covered by a linked resource, it probably does not need its own entry.

## Adding a New Section

If you believe an entire new section is warranted:

- Open an issue first to discuss scope before submitting a PR.
- The section must have at least 5 strong entries.
- It must not significantly overlap with an existing section.

## Updating Existing Entries

- If a link is broken, submit a PR with the corrected URL.
- If a description is inaccurate, submit a PR with the fix and a brief explanation in the PR description.
- If a resource has been abandoned, submit a PR to remove it.

## awesome-lint Compliance

This list targets compliance with [awesome-lint](https://github.com/sindresorhus/awesome-lint). Before submitting:

- Ensure Markdown is valid and consistently formatted.
- Use `-` for all list items (not `*` or `+`).
- Do not add trailing slashes to URLs.
- Headings must be properly nested (no H1 to H3 jumps).
